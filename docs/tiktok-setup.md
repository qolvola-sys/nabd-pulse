# ربط TikTok API — دليل مفصّل

الهدف: الحصول على `Client Key` و`Client Secret` وتفعيل الصلاحيات، حتى يقرأ خادم «نبض» منشورات كل حساب ومشاهداته.

> الوقت المتوقع: 20–30 دقيقة للتسجيل، ثم انتظار مراجعة TikTok (من يوم إلى أسبوعين حسب حالتك).

---

## 1) إنشاء حساب مطوّر

1. افتح <https://developers.tiktok.com/>.
2. سجّل الدخول بحساب TikTok (يفضّل حساب الشركة/المشروع).
3. أكمل بيانات المطوّر (الاسم، البريد، الدولة).

## 2) إنشاء التطبيق

1. **Manage apps** → **Connect an app**.
2. اختر اسماً واضحاً، مثال: `Nabd Analytics`.
3. اختر الفئة الأنسب (Productivity / Analytics).
4. بعد الإنشاء تظهر صفحة التطبيق وفيها:
   - `Client key`
   - `Client secret` (اضغط Show)

احتفظ بهما — لا تشاركهما ولا تضعهما داخل التطبيق أبداً. مكانهما الوحيد: `server/.env`.

## 3) إضافة المنتجات

من صفحة التطبيق → **Products** → أضف:

| المنتج | لماذا |
|---|---|
| **Login Kit** | تسجيل دخول كل حساب والحصول على توكن |
| **Display API** | قراءة معلومات الحساب والفيديوهات |

## 4) الصلاحيات (Scopes)

في إعدادات Login Kit أضف:

```
user.info.basic
user.info.stats
video.list
```

- `user.info.basic`: الاسم والصورة و`open_id`.
- `user.info.stats`: المتابعون، الإعجابات، عدد الفيديوهات.
- `video.list`: قائمة الفيديوهات ومشاهداتها — **الأهم**.

بدون `video.list` لن تحصل على المشاهدات.

## 5) Redirect URI

أضف في إعدادات التطبيق:

```
https://YOUR-SERVER/auth/tiktok/callback
```

شروط TikTok:

- HTTPS إلزامي (يُسمح بـ `http://localhost` للتجربة المحلية فقط).
- يجب أن يطابق حرفياً القيمة في `.env` (`TIKTOK_REDIRECT_URI`).
- لا مسافات ولا `/` زائدة.

## 6) وضع Sandbox

قبل الموافقة النهائية، يعمل التطبيق في **Sandbox**:

1. أضف حسابات TikTok التجريبية في **Sandbox → Target users** (حتى 10 حسابات عادةً).
2. اربطها من التطبيق: الحسابات → إضافة → ربط.
3. هذه الحسابات فقط ستعمل قبل المراجعة، وهذا كافٍ لتجربة النظام كاملاً.

## 7) طلب المراجعة (Production)

عند التقديم ستحتاج غالباً:

- **Privacy Policy** و**Terms of Service** على رابط عام.
- فيديو قصير يوضح: كيف يسجّل المستخدم الدخول، وكيف تظهر بياناته، وكيف يحذف حسابه.
- وصف واضح للاستخدام: «أداة تحليلات لمالك الحساب، لا تجمع بيانات مستخدمين آخرين».
- سبب طلب كل صلاحية.

نصائح تزيد فرصة القبول:

- اجعل الوصف بالإنكليزية واضحاً ومباشراً.
- أظهر شاشة «فصل الحساب/حذف البيانات» في الفيديو.
- لا تطلب صلاحيات لا تستخدمها.
- تأكد أن صفحة الخادم تعمل وHTTPS صالح.

## 8) ضبط الخادم

في `server/.env`:

```env
PUBLIC_BASE_URL=https://api.yourdomain.com
TIKTOK_CLIENT_KEY=your_client_key
TIKTOK_CLIENT_SECRET=your_client_secret
TIKTOK_REDIRECT_URI=https://api.yourdomain.com/auth/tiktok/callback
TIKTOK_SCOPES=user.info.basic,user.info.stats,video.list
DEMO_MODE=0
API_TOKEN=<مفتاح عشوائي طويل>
TOKEN_ENC_KEY=<مفتاح عشوائي 32 بايت>
```

ثم:

```bash
npm start
```

## 9) التحقق

```bash
curl https://api.yourdomain.com/health
# {"ok":true,...,"tiktokConfigured":true}
```

ثم من التطبيق: الإعدادات → حفظ واتصال → الحسابات → إضافة → ربط.

بعد نجاح الربط:

- يعود التطبيق تلقائياً عبر `nabd://oauth?status=ok`.
- يبدأ سحب المعلومات والمنشورات في الخلفية.
- تظهر الأرقام في الصفحة الرئيسية.

## 10) حدود يجب معرفتها

| الأمر | القيمة |
|---|---|
| صلاحية access token | 24 ساعة (يُجدَّد تلقائياً) |
| صلاحية refresh token | سنة |
| حد سحب الفيديوهات | 20 فيديو/طلب، مع cursor |
| عدد الحسابات | بلا حد تقني من نبض؛ كل حساب يحتاج ربطاً منفصلاً |
| `username` | **لا يعيده API**؛ نبض يعتمد على المعرف الذي أدخلته عند الإضافة |
| إجمالي مشاهدات الحساب | غير متاح كرقم واحد؛ نجمع مشاهدات المنشورات |

## مشاكل شائعة

| الرسالة | السبب |
|---|---|
| `invalid_client` | Client Key/Secret خطأ أو فيهما مسافة |
| `redirect_uri mismatch` | اختلاف حرفي بين `.env` ولوحة TikTok |
| `scope_not_authorized` | الصلاحية غير مضافة للتطبيق أو لم تُوافق بعد |
| `access_token_invalid` | التوكن انتهى؛ أعد الربط إذا فشل التجديد |
| `rate_limit_exceeded` | خفّض `SYNC_CONCURRENCY` وانتظر |
| لا تظهر أرقام بعد الربط | افتح تفاصيل الحساب واضغط «تحديث الإحصاءات» وراجع سجل الخادم |
